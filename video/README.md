## Content and timing

Follow [`../docs/demo_script.md`](../docs/demo_script.md). The planned structure is:

- 0:00–0:40 — problem and measurable claim;
- 0:40–1:15 — repository, data, evaluation transparency;
- 1:15–2:45 — live end-to-end product run;
- 2:45–3:50 — controlled comparison and metrics;
- 3:50–4:35 — critique, rough edges, and responsible-use boundary;
- 4:35–5:00 — conclusion and next evidence step.

## Quality checklist

- Face and screen are visible together.
- Narration is precise, confident, and succinct; avoid reading every label.
- Terminal/editor text is readable at 1080p where possible.
- API keys, notifications, bookmarks, and personal/confidential data are hidden.
- The demo shows one successful run and the human-approval message.
- The evaluation claim is described narrowly as component coverage.
- Final playback, audio, permissions, and link access are verified.
